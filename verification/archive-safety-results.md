# Archive safety — final verification 2026-11-25

Scope: complete FK configuration checks; immutable numbered ZIP parts; bounded
cleanup of abandoned work folders; a large seed fixture. Existing record selection,
relation graph ordering, CSV serializer, 7-Zip runner and group DELETE transaction
were not changed. DTSX/dtproj were regenerated by the existing package builder.

## Production behavior

- Validate reachable physical FKs before export, including all four delete rules,
  empty children, deeper descendants and composite keys (unsupported -> explicit error).
- Validate the computed member plan and refresh FK metadata before group deletion.
- Require source database VIEW DEFINITION; do not assume hidden metadata is complete.
- Build archive.pending in a work folder, verify with 7-Zip, then File.Move to a free
  yyyy_MM_dd.zip / yyyy_MM_dd__PARTn.zip without overwrite. Counter follows max ZIP part.
- Preserve every existing ZIP, including legacy retry ZIPs. Finalization only deletes
  recorded CSV/pending work files. Unexpected files/subfolders/links cause rejection.
- Keep verified archives after failures; retries may duplicate records by design.
- Session application lock in master protects one ArchiveRoot on a SQL instance;
  normal/error completion releases it. No new persistent batch-state table.
